O que são Agent Skills?

No ecossistema de Agentes de IA, as Skills (Habilidades) são pacotes modulares de instruções e scripts que estendem as capacidades do agente. Em vez de dar ao agente um prompt gigantesco com todas as tarefas possíveis do mundo, nós fornecemos a ele a capacidade de "aprender" e ativar habilidades específicas dinamicamente apenas quando necessário.

⚙️

Estrutura Modular

Uma Skill é encapsulada em uma pasta contendo instruções em Markdown (YAML frontmatter) e arquivos/scripts de suporte opcionais.

🎯

Ativação Dinâmica

A IA analisa a intenção do usuário e decide se alguma de suas Skills cadastradas deve ser acionada para resolver a tarefa.

🔌

Scripts de Suporte

Habilidades podem executar scripts (Python, JS) em segundo plano para interagir com APIs, bancos de dados ou o sistema de arquivos.

Laboratório Prático: Validador de Commits

Neste laboratório, os alunos aprenderão a implementar uma Skill para o agente chamada git-commit-helper. Essa skill ajudará o desenvolvedor a escrever mensagens de commits padronizadas segundo o Conventional Commits e executará um script para validar a mensagem.

Crie a Estrutura de Pastas

Skills de IA seguem uma convenção rígida de diretórios. Para a nossa skill funcionar, precisamos criar uma pasta com o nome da skill dentro do diretório de customizações (geralmente sob a pasta skills/):

Estrutura de Arquivos
meu-projeto/ └── .agents/ └── skills/ └── git-commit-helper/ ├── SKILL.md # Instruções e metadados └── scripts/ └── validate_commit.js # Script validador

💡 Dica do Instrutor: O arquivo SKILL.md é o coração da nossa Skill. É dele que o agente lê a descrição para saber se deve ou não ativar a habilidade.

Defina as Instruções em SKILL.md

Escreva o arquivo SKILL.md. Ele deve começar com o frontmatter YAML contendo name e description, seguido pelas instruções que guiarão a IA no comportamento desejado.

SKILL.md
--- name: "git-commit-helper" description: "Auxilia na geração de mensagens de commit padronizadas e valida o formato final" --- # Instruções de Comportamento Quando o usuário solicitar ajuda para fazer um commit ou salvar alterações no git: 1. Pergunte quais alterações foram feitas (se você não conseguir deduzi-las do contexto). 2. Escreva uma mensagem de commit de acordo com as regras do Conventional Commits. 3. Chame o script de validação de commit em scripts/validate_commit.js para verificar se está correto. 4. Apresente a mensagem formatada para o usuário.

Crie o Script de Validação

Agora criaremos o arquivo scripts/validate_commit.js que fará a validação técnica da string do commit via regex no Node.js.

scripts/validate_commit.js
const fs = require('fs'); // Padrão Conventional Commits básico: feat|fix|docs|style|refactor|test|chore(escopo): descrição const commitRegex = /^(feat|fix|docs|style|refactor|test|chore)(\([a-zA-Z0-9_-]+\))?: .{5,100}$/; const commitMsg = process.argv[2]; if (!commitMsg) { console.error("Erro: Nenhuma mensagem de commit fornecida."); process.exit(1); } if (commitRegex.test(commitMsg)) { console.log("✅ Mensagem válida de acordo com Conventional Commits!"); process.exit(0); } else { console.error("❌ Mensagem inválida. Padrão exigido: tipo(escopo): descrição"); process.exit(1); }

Ativação e Testes Práticos

Agora que os arquivos estão criados, você pode testar a Skill pedindo ao agente para gerar e validar uma mensagem.

🛠️ Exercício para o Aluno: Tente enviar o prompt: "Crie uma mensagem de commit para a adição da validação de formulário de login".

O agente deverá carregar a skill git-commit-helper, criar algo como feat(auth): add login form validation, e simular a execução do script com sucesso!
